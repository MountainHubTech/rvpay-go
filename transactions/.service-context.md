# Transactions Service — PawaPay Context

## Purpose
Transactions replaces legacy Deposits and owns:
- Merchants
- Customers
- Deposits
- Payouts

## Existing architecture
The service contains:
- `cmd/grpc-service/`
- `config/`
- `db/`
- `merchants/`
- `customers/`
- `deposits/`
- `payouts/`

It exposes gRPC and gRPC-Gateway APIs.

## PawaPay migration
Legacy `deposits/` already constructs and injects the PawaPay client.
Transactions must follow that established pattern.

The current PawaPay client repository is the SDK source of truth.
Only methods currently present in the SDK may be used.

## Configuration
Only:
- `PAWAPAY_API_URL`
- `PAWAPAY_API_KEY`

## Integration target
PawaPay is used by:
- Transactions deposits
- Transactions payouts

Do not change unrelated behavior.

## Testing
Provider calls must be testable without real PawaPay requests.
Use existing testing patterns.
