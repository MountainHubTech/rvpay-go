- HighLevel Marketplace INSTALL establishes RVPay tenancy (client + integration).
- Marketplace OAuth callback resolves the pre-established integration by `locationId`.
- The authorization code is exchanged exactly once.
- Existing state-based OAuth flow is preserved.

## Absolute rules
- ONLY change files in `clients/` directly in the INSTALL/OAuth call path and
  their directly affected repos/queries/tests.
- NEVER touch transactions, deposits, pawaPay, or any unrelated service.
- NEVER create or modify `platforms` records. The HighLevel platform already
  exists; resolve it by slug (`highlevel`) — do not call CreatePlatform.
- NEVER modify migrations or the schema unless the existing schema cannot
  support the change (prefer existing columns like `integrations.external_account_id`).
- NEVER alter secrets, .env, or deployment/infrastructure files.
- NO unrelated refactors or new abstractions "for style".
- Do NOT invent new database structures, queries, or patterns where an existing
  RVPay pattern supports the change.

## Follow existing conventions
- Copy `deposits/` / existing `clients/` patterns: folder layout, package names,
  constructor + dependency-injection style, `sqlc` + repository pattern.
- Preserve existing syntax, naming, error (`status.Error(codes.*)` / `translateError`),
  logging (structured zerolog), and repository error wrapping (`wrapError`,
  `wrapNotFound`, `repo.ErrNotFound/ErrDuplicate`).
- Repository methods go through the `sqlc.Querier` interface; never call the DB directly.

## Tests are mandatory
- Add/update focused unit tests for every changed behavior (INSTALL create/reuse,
  integration↔locationId mapping, callback resolution, single code exchange,
  state flow preserved).
- Run narrow changed-package tests first, then the clients-service suite.

## Context economy
- Use `clients/.clineignore.md` and `clients/.service-checkpoint.md` as the boundary.
- Read only files already identified plus their direct call graph. Keep notes short.
- Update `clients/.clinecheck.md` and `clients/.service-checkpoint.md` after each task.

## Out of scope / forbidden
- Platform creation, schema changes, infrastructure, secrets, unrelated refactors,
  generated/dependency edits unless required by a direct source change.
