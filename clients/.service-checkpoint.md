# .service-checkpoint — clients/ architecture (context for Agent 02)

## Entry point / wiring
- `cmd/grpc-service/main.go`: builds repos from `clientsRepo.Do()` querier, registers
  provider registry, builds `oauth.NewService(...)` and webhooks, then registers HTTP
  handlers. HighLevel platform is assumed to already exist (no platform bootstrap here).

## HTTP endpoints (Agents 02 call path)
- `GET /oauth/callback` → `http.OAuthHandler.Callback` → `oauth.Service.HandleCallback(code, state)`
- `POST /webhooks/highlevel` → `http.WebhookHandler.HighLevel` → `webhooks.Service.ProcessWebhook`

## OAuth flow — `oauth/service.go`
- `HandleCallback(code, state)`:
  - `state != ""`: `OAuthStateRepo.Consume(state)` (validates + atomic one-shot),
    then `ProcessCallback(clientID, platformID, code, state)`.
  - `state == ""` (Marketplace): already exchanges code once (`ExchangeCode`),
    resolves integration by `external_account_id = locationId`, falls back to
    `payment_provider_configs.location_id`, then calls `ProcessCallback(..., code, ...)`.
- `ProcessCallback(clientID, platformID, code, state)`:
  - Looks up platform (enabled) + client (ACTIVE) + provider.
  - **EXCHANGES THE CODE AGAIN (`ExchangeCode`)** — this is the double-exchange bug for
    the Marketplace (no-state) path. Reuses a pre-provisioned `CREATED` integration
    (sets ACTIVE) or creates one; persists `OAuthTokenRepo.Create`; then
    `RegisterProvider` (best-effort, non-fatal).

## Webhook flow — INSTALL
- `webhooks/service.go ProcessWebhook`: verify signature → `ParseEvent` → resolve
  `integrationID` by `external_account_id` then `payment_provider_configs.location_id`.
  - For INSTALL, if neither resolves it returns `ErrIntegrationNotFound` (no autoprovisioning today).
  - Records event idempotently (`webhook_events` unique `(integration_id, provider_event_id)`).
  - Dispatches INSTALL to `HighLevelWebhookDispatcher`.
- `providers/highlevel_webhook.go handleIntegrationInstalled`: resolves integration the
  same way; only creates/finds `payment_provider_configs`. **Does NOT create client or
  integration.** Dispatcher has only `integrationsRepo` + `configRepo` (no clients/platforms repos).

## GHL webhook payload mapping (`ParseEvent`)
- `appId → IntegrationID` (GHL app id, NOT an RVPay UUID)
- `companyId → ClientID`, `locationId → LocationID`, `webhookId → ProviderEventID`
- Event types: `INSTALL` / `integration.installed`, etc. `INSTALL` is the tenancy hook.

## DB schema / queries (do not change migrations)
- `clients(id, client_name, status ENUM, ...)`; lookup by id/name; unique by none on name.
- `platforms(id, slug UNIQUE, enabled, ...)`; resolve HighLevel by `slug='highlevel'`.
  `GetPlatformBySlug` exists in `clients.sql` query + `PlatformRepo`.
- `integrations(id, client_id, platform_id, external_account_id, status, ...)`
  - `uq_integration_client_platform UNIQUE (client_id, platform_id)`
  - `idx_integrations_external_account_id` (non-unique index on `external_account_id`)
  - `CreateIntegration(client_id, platform_id, external_account_id, status)`
  - `GetIntegrationByExternalAccountID`, `GetIntegrationByClientAndPlatform`,
    `UpdateStatus`.
  - No SQL update for `external_account_id` currently exists — set it at Create time
    (or add an `UpdateExternalAccountID` query + sqlc regen only if needed).
- `oauth_tokens(integration_id UNIQUE)`; `oauth_states(state UNIQUE, consumed_at, expires_at)`.
- `payment_provider_configs(integration_id UNIQUE, location_id INDEX)` — secondary
  `locationId → integration` mapping created on INSTALL/provider registration.

## Deterministic resolution order for `locationId`
1. `integration.external_account_id = locationId` (authoritative provisioning mapping).
2. `payment_provider_configs.location_id = locationId` (registration mapping).
Then integration → `client_id` + `platform_id`.

## Repos relevant to Agent 02

- `IntegrationRepo`: Create, GetByExternalAccountID, GetByClientAndPlatform, UpdateStatus.
- `PaymentProviderConfigRepo`: GetByIntegrationID, GetByLocationID, Create, Update.

## Risks / gotchas
- Double `ExchangeCode` for Marketplace callback (must fix; keep state flow single-exchange).
- INSTALL must provision client+integration before `webhook_events` insert (FK) and make
  it idempotent under concurrent duplicates.
- No existing SQL to set `external_account_id` on update; assign at Create unless a query
  is added deliberately.
- `external_account_id` is intentionally non-unique — guard the external idempotency at
  the service layer (locationId → one integration per client) to avoid ambiguity.
- Do NOT create/modify the HighLevel platform.
- Platform resolution by `slug="highlevel"`; name is "HighLevel".

## Avoid
- `transactions/`, `deposits/`, pawaPay code, `grpc/go/`, generated/dependency trees,
  `.env`/secrets, infrastructure/CloudFormation, unrelated refactors.
- `clients/payments/` and `providers/highlevel_payment_provider.go` unless the marker
  indicates they are affected (GHL Custom Payment Provider ≠ Marketplace INSTALL/OAuth).

## AGENT 02 ROUND 2 UPDATE — HandleCallback creates tenant during installation

The stateless Marketplace OAuth callback NO LONGER assumes an integration already
exists. Current behavior (`clients/oauth/service.go` `HandleCallback`, `state == ""`):
1. Exchange the code once → `tokenResp.LocationID`.
2. Resolve the existing HighLevel platform by slug `"highlevel"` (`PlatformRepo.GetBySlug`).
   Platform creation is out of scope — a missing platform returns `ErrPlatformNotFound`.
3. Create (idempotent) the tenant client named `highlevel-<locationId>` (ACTIVE).
4. Create (idempotent) the client's integration with `external_account_id = locationId`,
   status `CREATED`.
5. Continue with the already-exchanged token via `processCallbackWithToken` (which
   activates the CREATED integration, persists the OAuth token, and best-effort
   registers the HighLevel Custom Payment Provider).

This installs the RVPay tenant during installation (NOT before), fixing the GHL
Marketplace install that previously broke because no integration existed yet.
Corresponding tests updated in `clients/oauth/service_test.go`.

## Agent 04 — Implementation

### Problem
GHL v3 registers the Custom Payment Provider via the create-integration
association (locationId in QUERY, provider metadata in body). The old flow sent
only `{"locationId":...}` in the body (metadata never registered) and attempted
metadata registration through the connect endpoint (which is actually the
live/test-keys endpoint). Credentials were also logged (OAuth code, access
token, the token-request form incl. clientSecret, and the DB DSN), and
`processCallbackWithToken` had integration creation commented out, leaving the
integration zero-valued for flows without a pre-provisioned integration.

### Implementation
- providers/payment_provider.go: removed CreateProviderConfig; association now
  takes ProviderConfig; documented association vs connect (v3 keys endpoint).
- providers/highlevel_payment_provider.go: CreateProviderAssociation sends
  locationId as a query parameter + provider metadata in the JSON body; Version: v3; Bearer.
- oauth/service.go RegisterProvider: associate (v3) -> best-effort fetch existing
  config -> persist local, reusing existing api_key; no blanket 400/422-as-exists.
- oauth/service.go processCallbackWithToken: create + activate integration
  (external_account_id = locationId) when none exists.
- providers/highlevel.go: removed token-request form logging (client secret/code).
- cmd/grpc-service/main.go: removed DB-DSN print.
- Tests: association contract assertions (method/path, Version, Bearer, query
  locationId, metadata body, no locationId in body); fetch-failure non-fatal;
  integration auto-create.

### Files changed
clients/oauth/service.go, service_test.go; clients/providers/payment_provider.go,
highlevel_payment_provider.go, highlevel_payment_provider_test.go, highlevel.go;
clients/cmd/grpc-service/main.go.

### DB changes
None. Reused existing payment_provider_configs columns. No migration, query, or
sqlc regeneration.

### Tests

- go vet ./clients/...: clean.
- gofmt: formatted; files kept as repo CRLF (gofmt -d shows only CRLF diffs).
