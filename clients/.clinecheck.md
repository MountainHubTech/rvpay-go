## 4. v3 endpoint findings (authoritative — marketplace.gohighlevel.com v3 docs)
1. **Provider association (create integration)** — `POST /payments/custom-provider/provider`, header `Version: v3`.
   - `locationId` is a **QUERY** parameter (required), NOT in the body.
   - Body (all required): `name`, `description`, `paymentsUrl`, `queryUrl`,
     `imageUrl`, `supportsSubscriptionSchedule` (bool).
   - Response: `_id`, `name`, `description`, `paymentsUrl`, `queryUrl`, `imageUrl`,
     `locationId`, `marketplaceAppId`, `paymentProvider`, `deleted`, `createdAt`,
     `updatedAt`, `traceId`.
   - **This call registers the provider NAME/URLs/LOGO shown in HighLevel.**
2. **Provider configuration/connect** — `POST /payments/custom-provider/connect`, header `Version: v3`.
   - `locationId` is a **QUERY** parameter (required).
   - Body: `live:{apiKey,publishableKey}` and `test:{apiKey,publishableKey}`.
   - Response: same provider shape as create-integration.
   - This endpoint stores LIVE/TEST API keys — NOT provider metadata.
3. **Fetch config** — `GET /payments/custom-provider/connect`, `locationId` query param, `Version: v3`; returns provider shape.
4. **Disconnect config** — `DELETE /payments/custom-provider/connect`, `locationId` query param. (Separate sorry-typo: `Delete` integration endpoint also exists.)
5. **Token / user type** — `POST /oauth/token` (form-urlencoded). Request fields are
   **snake_case**: `client_id`, `client_secret`, `grant_type`
   (`authorization_code`|`refresh_token`|`client_credentials`), `code`,
   `refresh_token`, `user_type` (`Company`|`Location`), `redirect_uri`.
   Response is **camelCase**: `access_token`, `token_type`, `expires_in`,
   `refresh_token`, `scope`, `userType`, `locationId`, `companyId`,
   `approvedLocations`, `userId`, `planId`, `isBulkInstallation`,
   `installToFutureLocations`, `approveAllLocations`.
   - `locationId` present only for **Sub-Account (Location)** tokens; `Company`
     tokens carry `companyId` + `approvedLocations` + bulk flags.
5a. Auth URL `https://marketplace.gohighlevel.com/oauth/chooselocation` (current code
   matches); token URL `https://services.leadconnectorhq.com/oauth/token`.
6. **Required payment scopes**: `payments/orders.readonly`, `payments/orders.write`,
   `payments/subscriptions.readonly`, `payments/transactions.readonly`,
   `payments/custom-provider.readonly`, `payments/custom-provider.write`,
   `products.readonly`, `products/prices.readonly`. (Current provider uses `["read","write"]` — insufficient.)
7. **Agency vs location install**: `user_type=Location` → per-sub-account token with
   `locationId`; `user_type=Company` → agency token (bulk/`approvedLocations`).
   RVPay targets Sub-accounts, so `user_type=Location` is correct — but field name
   and Company-token handling are open questions.
8. **Existing association/config**: repeated create for same location errors; explicit
   delete/disconnect endpoints exist. Prefer fetch-exists → reuse (or delete→create)
   over a status-code “already exists” guess.
9. **Which response is provider metadata**: the **Create/Get integration**
   (`/payments/custom-provider/provider`) and **FetchConfig** (`GET .../connect`)
   both return the provider metadata shape; metadata is REGISTERED by the
   integration/association call. `connect` is only for live/test keys.

## 5. Current defects in `HighLevelPaymentProviderClient` (Agent 04 must fix)
- D1 `CreateProviderAssociation` (`POST /payments/custom-provider/provider`)
  sends `{"locationId":...}` in the BODY and NO provider metadata. v3 wants
  `locationId` in QUERY and metadata (`name,description,paymentsUrl,queryUrl,
  imageUrl,supports..`) in the BODY. Metadata never registered; likely 422.
- D2 `CreateProviderConfig` (`POST /payments/custom-provider/connect`) sends provider
  METADATA and puts `locationId` in the BODY. v3 wants `locationId` in QUERY and a
  BODY of `live`/`test` api-key objects. Keys never stored; likely 422.
- D3 `FetchProviderConfig` (`GET /payments/custom-provider/connect`): `locationId`
  query + camelCase parse — CORRECT. Keep.
- D4 `oauth/service.go RegisterProvider` treats `ErrBadRequest`/`ErrUnprocessableEntity`
  from BOTH association & connect as “already exists” and merely fetches. Conflates
  contract errors with duplicates. Replace with explicit fetch-confirm-or-(re)create.
- D5 OAuth token field casing: `providers/highlevel.go` sends camelCase
  (`clientId,clientSecret,grantType,redirectUri,userType`) for `POST /oauth/token`;
  v3 doc specifies snake_case (`client_id,client_secret,grant_type,redirect_uri,
  user_type`). Same in `RefreshToken`. Verify on a real install; likely switch to
  snake_case.
- D6 Scopes `["read","write"]` lack required `payments/*`,`products/*` scopes (§4.6).
- D7 Credential/code leakage via logs (violates rules):
  - `oauth/service.go` logs the OAuth `code` (~L194).
  - `oauth/service.go` logs `tokenResp.AccessToken` (~L399).
  - `providers/highlevel.go` logs full token-request `data` incl. `clientSecret` (~L156).
  - `cmd/grpc-service/main.go getPostgresConnectionURL` prints DB DSN (password).
- D8 Local `payment_provider_configs` row (dev tenant) is empty of provider
  metadata/location (name/urls/location empty; only api_key set). Root cause D1/D2;
  fixing + persisting fetched/returned config should repopulate it.
- D9 `providers.TokenResponse` has no `userType`/`companyId`/`approvedLocations`; a
  Company token would make the stateless callback return `ErrMissingLocationID`.
- D10 Re-install/duplicate: with delete/disconnect endpoints available, replace the
  “create→on 4xx fetch” heuristic with a deterministic exists?→fetch : create flow.

## Agent 04 — IMPLEMENTATION (appended, historical findings kept above)

### Problem
- GHL v3 require the Custom Provider association to place `locationId` in the
  QUERY and provider metadata (name, description, paymentsUrl, queryUrl,
  imageUrl, supportsSubscriptionSchedule) in the body. The prior
  `CreateProviderAssociation` sent only `{"locationId":...}` in the body and
  never registered metadata.
- The connect endpoint (`POST /payments/custom-provider/connect`) stores
  live/test processing keys and is NOT the metadata registration step. The old
  flow called it with metadata, so provider metadata was never registered.
- Credentials were logged: the OAuth `code`, the access token, the full token
  request (incl. clientSecret), and the DB DSN.
- `processCallbackWithToken` had the integration-creation block commented out,
  so when no integration existed the integration stayed the zero value -> token
  persisted against an empty ID and provider registration failed with NotFound.

### Implementation
1. `providers/payment_provider.go`: dropped `CreateProviderConfig`; kept
   `CreateProviderAssociation(accessToken, ProviderConfig)`, `FetchProviderConfig`,
   `DisconnectProvider`. Documented the v3 association vs connect distinction.
2. `providers/highlevel_payment_provider.go`: `CreateProviderAssociation` now
   sends `locationId` as a QUERY parameter and the provider metadata in the JSON
   body (`POST /payments/custom-provider/provider?locationId=<id>`, `Version: v3`,
   Bearer). Removed the misconceived `CreateProviderConfig`.
3. `oauth/service.go RegisterProvider`: metadata is the source of truth;
   association (v3) -> best-effort fetch of existing config (persist genuine
   remote metadata) -> local persistence reusing an existing api_key. No longer
   classifies every 400/422 as already-exists; only a confirmed remote fetch is
   treated as idempotent. Removed credential logs.
4. `oauth/service.go processCallbackWithToken`: when no integration exists for
   client/platform, create one (CREATED -> ACTIVE) with `external_account_id =
   locationId` and activate it, mirroring the stateless path. Fixes token
   persistence + registration for the state-based / no-pre-provisioned case.
5. `providers/highlevel.go`: removed logging of the full token request form
   (client secret / code leak).
6. `cmd/grpc-service/main.go`: removed DB-DSN print (password leak).
7. Tests updated: `providers/highlevel_payment_provider_test.go` (association
   contract: method/path, Version v3, Bearer, query locationId, metadata body,
   no locationId in body); `oauth/service_test.go` (fetch-config failure now
   non-fatal; integration auto-create).
