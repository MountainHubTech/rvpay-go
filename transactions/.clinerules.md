# Transactions PawaPay Rules

## Scope
Only implement PawaPay in `transactions/`.

## Source of truth
- Current `pawapay_client` API is authoritative.
- Legacy `deposits/` is the wiring and style guide.
- Existing Transactions code is the domain contract.

## Coding
- Do not invent SDK syntax.
- Do not rename public APIs.
- Do not redesign architecture.
- Prefer the smallest change.
- Follow existing Go patterns.
- Run gofmt on changed Go files.

## Environment
Only:
- `PAWAPAY_API_URL`
- `PAWAPAY_API_KEY`

## Tests
Tests are required.
Do not call the real PawaPay API in tests.
Use existing project testing patterns.

## Context
Read `transactions/.service-context.md` and `transactions/.service-checkpoint.md` before work.
Keep agent output short.
Record decisions in the checkpoint.

## Tracking
After every task update:
- `transactions/.clinecheck.md`
- `transactions/.service-context.md`
- `transactions/.service-checkpoint.md`

## Stop
Stop when current PawaPay deposit and payout methods are integrated and tested.
Do not implement callbacks, reconciliation, retries, webhooks, or future SDK features.
