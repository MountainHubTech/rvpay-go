# Cline Project Rules — Dockerization Sequence

## Mission

Prepare this Next.js application for production Dockerization through the numbered Cline agents (01–06). This sequence does **not** modernize the application; it only makes it deployable as a production Docker container.

## Absolute Rules

1. NEVER overwrite existing working code.
2. NEVER refactor the application unless explicitly instructed by an agent file.
3. NEVER modify application source code in Agent 00.
4. NEVER change dependencies unless an agent file proves it is strictly necessary.
5. NEVER perform dependency upgrades.
6. NEVER invent environment variables, AWS resources, ports, commands, or deployment architecture.
7. NEVER commit secrets or real credentials.
8. NEVER create Docker files, Makefile, AWS infrastructure, or CI/CD in Agent 00.
9. NEVER replace existing patterns with preferred patterns.

## Operating Principles

1. Read narrowly. Do not recursively inspect the whole repository unless a required fact cannot be established otherwise.
2. Prefer package/config metadata over source-code exploration.
3. Preserve the existing application.
4. Dockerization is the goal; modernization is not.
5. Keep later agents independent and cheap by recording facts once.
6. If a fact is unknown, record `UNKNOWN — verify in Agent N` rather than guessing.
7. Do not install packages merely to investigate.
8. Do not make unrelated cleanup changes.

## Project-Control Files

The following files are the shared context for all agents in this sequence:

- `.clinerules.md` — this file; the rules all agents must follow
- `.clineignore.md` — areas/files agents should avoid reading unless directly required
- `.project-context.md` — stable facts, decisions, and unknowns that constrain all agents
- `.project-checkpoint.md` — chronological checkpoint ledger with reading map and completion records
- `.clinecheck.md` — lightweight verification checklist for the entire sequence
- `.project-next-steps` — reserved for Agent 06; AWS deployment guide only after Dockerization completes

## Checkpoint Protocol

- Each future agent must append its result to `.project-checkpoint.md` rather than rewriting prior records.
- Each completion record must contain: agent, date, status, files changed, checks run, findings, decisions, unresolved issues, next-agent handoff, and exact additional reading required.
- Agents may mark checks in `.clinecheck.md` only if they actually verified them.

## Next.js 16 Documentation

`AGENTS.md` explicitly requires checking the installed Next.js 16 documentation (`node_modules/next/dist/docs/`) before writing Next.js code. Heed deprecation notices.

## Final Rule

If uncertain, inspect the existing application and the project-control files before creating anything.
