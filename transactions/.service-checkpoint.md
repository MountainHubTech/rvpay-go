## Decisions
- Bump `pawapay_client` to main HEAD `v0.0.0-20260813104302-0841c026f9f4`. This BREAKS legacy `deposits/` compilation (repo-wide `go mod tidy` fails because legacy `deposits/` imports the removed `pawapay_client/config`) - explicitly approved by the user. `deposits/` was NOT modified.
- Scope limited to Transactions. Legacy `deposits/` used only as the wiring/style guide.
- Only `PAWAPAY_API_URL` and `PAWAPAY_API_KEY` are allowed.
- Only current SDK methods used: `Deposits.InitiateDeposit` and `Payouts.InitiatePayout`.
- No DepositStatus, PayoutStatus, Resend*Callback, Toolkit, callbacks, reconciliation, or retries.
- Payout recipient phone number is assumed to be the `destination_reference` field.
- SDK deposits/payouts packages are aliased (`pawapaydeposits` / `pawapaypayouts`) to avoid colliding with the local `deposits`/`payouts` packages.
- The validated local `provider`/`phoneNumber` variables are used for the SDK request (not the possibly-empty fields on the repo-returned struct).

## Risks / notes
- Repository-wide `go test ./...` will fail to build the legacy `deposits/` package after the bump. Expected/accepted. Validate with `go test ./transactions/...`.
- Provider is not mockable (no interface seam); tests use `httptest.Server` + `NewClient(srv.URL, "test-key")`.
- Amount is passed to the SDK as a decimal string, not `pgtype.Numeric` or `float64`.
