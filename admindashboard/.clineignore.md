# Cline Ignore — Dockerization Sequence

This is a **project guidance file** for the Dockerization agent sequence. It is not Cline's native ignore mechanism. Agents should treat the areas below as off-limits unless a task explicitly requires reading them.

## Areas to Avoid Reading Unless Directly Required

- `node_modules/` — installed dependencies; never inspect
- `.next/` — Next.js build output; never inspect
- `build/`, `out/`, `dist/` — build/output directories
- `coverage/` — test coverage output
- `.env`, `.env.local`, `.env.*.local` — local environment files; never read or commit
- `.git/` — version control internals
- `package-lock.json` — only read if a task explicitly requires lockfile verification
- Generated caches (`.cache/`, `.turbo/`, etc.)

## General Guidance

- Avoid broad source-tree rereads when `.project-context.md` and `.project-checkpoint.md` already answer the question.
- Prefer package/config metadata over source-code exploration.
- Read only the files listed in the task's reading map.
- If a fact is unknown, record `UNKNOWN — verify in Agent N` rather than guessing.
