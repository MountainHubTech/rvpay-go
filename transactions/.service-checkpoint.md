- Bump `pawapay_client` to main HEAD `v0.0.0-20260813104302-0841c026f9f4`. This BREAKS legacy `deposits/` compilation (repo-wide `go mod tidy` fails because legacy `deposits/` imports the removed `pawapay_client/config`) - explicitly approved by the user. `deposits/` was NOT modified.

- The validated local `provider`/`phoneNumber` variables are used for the SDK request (not the possibly-empty fields on the repo-returned struct).

## Follow-up: Legacy deposits service aligned with bumped pawapay_client

### Context
The legacy `deposits/` service still referenced the old `pawapay_client/config` API
(`model.Deposit`, `DepositsService.InititateDeposit`), which the bumped SDK
(`v0.0.0-20260813104302-0841c026f9f4`) removed. This broke repo-wide compilation and `go mod tidy`.

### Changes
- `deposits/deposits/service.go`
  - Removed `model "github.com/I-Frostbyte/pawapay_client/config"` import.
  - Added `pawapaydeposits "github.com/I-Frostbyte/pawapay_client/deposits"` and `strconv`.
  - Replaced the `model.Deposit` + `DepositsService.InititateDeposit(&deposit)` call with
    `pawapay.Deposits.InitiateDeposit(ctx, &pawapaydeposits.InitiateDepositRequest{...})`,
    passing the amount as a decimal string via `strconv.FormatFloat(amount.Float64, 'f', 2, 64)`.
- `deposits/deposits/service_test.go`
  - Added `TestInitiateDepositSuccess` (using `httptest.Server` + `NewClient(srv.URL, "test-key")`
    with mocked `DepositsRepo`/`Querier`) verifying the new deposit request path.
  - Added `TestInitiateDepositProviderError` (HTTP 500) expecting `codes.Internal`.
- `deposits/cmd/grpc-service/main.go`
  - No change required; it already constructs `pawapay_client.NewClient(config.APIURL, config.APIKey)`
    and passes `*pawapayClient` to `deposits.NewDepositsService`.
